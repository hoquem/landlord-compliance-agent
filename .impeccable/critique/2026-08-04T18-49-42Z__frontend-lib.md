## Anti-Patterns Verdict

**LLM assessment:** does not read as AI-generated. Warm dark at OKLCH hue 70
is genuinely uncommon for this category, no card grid, no hero metric, no
gradient, no glassmorphism, no side-stripe. The failure is the opposite of
slop: correct restraint, under-composed.

**Deterministic scan:** unavailable. `detect.mjs` reports "bundled detector
not found" after a real attempt. It targets markup, not Dart, so its value
here would have been limited regardless.

**Browser evidence:** sign-in inspected at 1440x900. Shell screens NOT
inspected (reaching them needs a real Google sign-in). Narrow-width capture
failed silently; the responsive claim rests on widget tests, which do
discriminate.

## Priority Issues

### [P0] The app contacts Google on every page load
Measured, three requests: `canvaskit.wasm` and `canvaskit.js` from
`www.gstatic.com`, and a Roboto `woff2` from `fonts.gstatic.com`. The
Flutter tool injects `FLUTTER_WEB_CANVASKIT_URL=https://www.gstatic.com/...`
unless `--dart-define=UseLocalCanvasKit=true`, while already copying
CanvasKit into `build/web/canvaskit/` — the bytes ship and go unused.

Fix: add the define, rebuild, then **re-measure**. Whether it also removes
the `fonts.gstatic.com` Roboto fetch is unverified; if it survives, a
bundled fallback is the remaining lever.

### [P0] Four documents asserted the opposite, unverified
DESIGN.md, `pubspec.yaml`, `tokens.dart` and commit `009da2d` all claimed
that bundling Inter keeps the user's IP off Google's CDN. Corrected in the
three files; the commit stands per the no-amend rule. The repo's own rule —
name the test or say you did not check — was broken in four places at once.
The test belongs in **Task 23's E2E smoke**: assert no external origins.

### [P1] Bundle weight was reported upside down
Inter's 782 KB was flagged; `canvaskit.wasm` at 5.6 MB was not measured at
all. Subsetting the font saves a few hundred KB; self-hosting CanvasKit is
where both the privacy fix and the real weight question live.

### [P2] The sign-in screen contradicts its own comment
`sign_in_screen.dart` says "a sign-in screen centred in 1400px of nothing is
the SaaS default; this is a doorway, and a doorway is narrow." The render is
a 380px column floating dead-centre in a 1440px void. Same
assert-without-enforcement pattern as the P0.

### [P2] No status, no errors, anywhere
OAuth is a full-page redirect: press the button and nothing visibly happens.
If Supabase is unreachable or the provider refuses, there is no error state
in the app at all. Heuristics 1 and 9 score lowest for this reason.

## Minor Observations
- Button label centred; every other element left-aligned.
- All four Inter weights preload on a screen using three.
- `document.fonts.check('400 16px Inter')` returns `true` against an empty
  font set under CanvasKit — a false positive worth knowing, since it is the
  first check anyone reaches for.
- No light/dark toggle, though both themes are fully built and tested.
